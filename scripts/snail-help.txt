Usage: snail-scheme build --target TARGET [--release] FILE
       snail-scheme run --target TARGET [--release] FILE [ARGUMENT ...]
       snail-scheme wat --target node|wasmtime|browser FILE
       snail-scheme build [--release] PROJECT BUILD-TARGET
       snail-scheme run PROJECT RUN-TARGET [ARGUMENT ...]
       snail-scheme lsp
       snail-scheme format [--width N] [--check | --write] [FILE ...]

build compiles the script FILE for TARGET: node, wasmtime or browser. Its
workspace is the nearest folder above it that holds src/, where every
import resolves. The output, build/PATH in the workspace, where PATH is
FILE's path there without its extension, is a link to a completed
generation: the program's manifest and a store/ view of its modules and
linked files, links into build/.snail-store, or copies with --release.
A browser build adds the browser host and the public/ folder beside FILE.

run builds FILE as build does, then becomes its program in the current
directory, with the ARGUMENTs, retaining terminal IO, exit status and
signals: on Node for node, on build/snail run-wasm for wasmtime.

wat prints the WebAssembly text of FILE's whole program.

The PROJECT forms build and run a target of PROJECT/project.datum, until
applications become scripts.

lsp serves the Language Server Protocol on standard input and output for
the folder an editor opens: diagnostics from each saved build, formatting,
hover, definitions and colours. Zed and VS Code start it through
editors/zed and editors/vscode.

format prints standard input formatted, or with --check fails for each FILE
not formatted, or with --write formats each FILE in place, at --width
columns (100 by default).

  -h, --help       Show this help.
