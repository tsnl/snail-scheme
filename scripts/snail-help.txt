Usage: snail build [--release] [--error-format=text|json] PROJECT BUILD-TARGET
       snail run [--error-format=text|json] PROJECT RUN-TARGET [ARGUMENT ...]
       snail dev [--port PORT] PROJECT

build reads PROJECT/project.datum and publishes the named target into
PROJECT/build/TARGET. Each output directory is a link to a completed
generation; earlier generations remain until explicitly removed. --release
requests full optimization. Browser targets package their program, browser
runtime and public directory. Put index.html in public; no page is generated.

run builds the named run-target's program and executes that completed generation
in the current directory. Configured arguments precede ARGUMENTs. The command
becomes the application process, retaining terminal IO, exit status and signals.

dev keeps one native project compiler running, watches disk and serves an
editor at http://127.0.0.1:PORT/ (8000 by default, 0 chooses a free port).
Save writes disk; the shared watcher triggers compilation. External edits
update clean editor buffers and report conflicts for unsaved buffers.
Application launching/reloading is not integrated into dev yet.

  -h, --help       Show this help.
  --error-format=text|json
                   Render build/run diagnostics on stderr as text (default)
                   or one JSON object per diagnostic. Place before PROJECT.
                   Does not change successful stdout or application output.

Text diagnostics use ERROR/WARNING/INFO labels and … for notes, with terminal color.
NO_COLOR disables color; FORCE_COLOR=1 forces it and FORCE_COLOR=0 disables it.
