# SFIR: six canonical workloads, 15 October 2026

All 33 eligible routes completed one warmup and five measured fresh processes
on CPU 2. The 198 scheduled processes passed their canonical predicates, and
post-run verification confirmed the frozen inputs, sources, toolchain and
artifacts. Measurement ran from 07:55:28 to 07:59:08 UTC after every collaborating
worker confirmed its CPU jobs were terminal. Compilation and instrumented
validation occurred beforehand and contribute no samples.

SFIR's Fibfp is close to Rust and faster than original Chez; native Ack is also
competitive. The character-at-a-time Cat and WC ports remain substantially
slower than original Chez and Rust. The continuation workloads show why both
Chez controls matter: the adapted continuation representation can be faster
than the original call/cc workload.

Rust FIBC additionally calls `black_box(x + 1)` on **each** Peano increment.
SFIR FIBC retains ordinary `succ`/`pred` recurrence with opacity only at its
original workload input/identity boundaries. This difference restricts Rust's
optimization freedom; its ratios do not isolate compiler quality. The campaign
preserves both recorded sources. No claim is made that a particular optimizer
collapsed the SFIR recurrence.

Node is 24.19.0 with V8 13.6.233.17-node.51; Chez is 10.4.1; Rust is 1.95.0
(`59807616e1fa2540724bfbac14d7976d7e4a3860`, LLVM 22.1.2). The selected Rust
sysroot and five locked crate sources were copied before compilation. Both
SFIR targets use the same canonical source. The native helper received the
Binaryen-optimized V8 program, then ran Binaryen **a second time** before LLVM
lowering and the separate clean entry/provider. The earlier claim that both
targets used an identical optimized module was incorrect: the retained hashes
differ for all six cases. The [optimization audit](20261015-native-optimization-audit.json)
records both modules, LLVM output and executable identities. These unchanged
samples describe that twice-optimized native pipeline. Runtime-backed Wasm
uses its frozen Rust scalar provider.

The timers retain the canonical repeated workers and full final predicates.
Source-specific harness operations remain as authored. Benchmark parameter
loading precedes the guest clock; the repeated file reads and writes in Cat/WC
remain inside it. Final resource cleanup follows the clock. Additional complete
Cat output-byte checks happen after the clock. A fresh-process warmup warms
shared machine state; it does not preserve V8 JIT state for the next process.
Any V8 tiering that occurs during the canonical workload remains part of its
time; module loading and instantiation precede the clock.

The default Rust Wasm Ack stack failure remains an explicit failed route.
There is no substitute result or time for it. Ack and Fibfp have no adapted
Chez control. This report covers six workloads, not all 57. Historical strict
reports used CPU 5 and different frozen revisions; these CPU-2 absolute times
