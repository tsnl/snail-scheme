# Adapted Chez numeric boundary

This is correctness evidence for source commit `6c89789`, depending on the
reusable numeric libraries in `6925f1c`. It adds no clean performance samples
and does not establish complete compiler-workload coverage. The latter remains
pending in the [compiler port contract](../../strict-suite/compiler-port.md).

Parent integration keeps the reviewed bridge source bytes unchanged. Its
independent archive audit checked all 648 file contents and all 288 terminal
command records; formatting, Python compilation and whitespace checks passed
on the integrated stack. The only cherry-pick overlap selected the bridge's
more precise diagnostic that benchmark counts must fit an exact I64.

The bridge executes the unchanged Integer, Rational, Number, Datum and reader
library bodies in separate lexical scopes. Only their scalar ABI uses Chez
services. Owned text handles cache one validated lexical classification;
arbitrary values retain exact digit fields until the shared Scheme arithmetic
constructs them. Explicit static annotations and overload declarations disappear
under Chez, and callers use named concrete numeric operations. Chez host vectors
represent records and handles; Snail uses its own concrete storage and runtime
token IDs. These controls do not claim identical allocation or host primitive
costs.

The Number cases include arbitrary integers and rationals, mixed exact/inexact
comparison, promotion, complex components, signed zero, subnormal projections,
decimal/radix input and numeric failures. The oracle fixture resolves ten
statically selected Number operations to their named library functions; every
such edit is retained. It changes no numeric library body.

The scalar cases inspect lexical metadata without constructing impossible huge
powers. They cover complete exact-decimal grammar, effective scale at both
I64 bounds, zero with a huge valid exponent, diagnostic versus invalid syntax,
rectangular/polar components and typed field rejection. A diagnostic on the
left stops component parsing; an invalid left component does not hide a right
diagnostic. Closed-handle failure takes precedence over component-kind failure.
Rust ABI failures terminate through WASI, so negative guest cases use separate
processes. Locally caught Chez errors only test the control's internal ownership
state; they do not imply recoverable guest errors.

Formatting compares the exact Rust `float_text` implementation with the Chez
boundary. The 20,084 distinct patterns include both signs, zero, subnormal and
normal boundaries, exponent-layout transitions, neighbors of selected powers
of ten, infinities, NaNs and 20,000 seeded random bit patterns. This is a finite
compatibility corpus, not an exhaustive proof of shortest-digit selection for
all binary64 values. Chez's R6RS subnormal precision suffix is removed before
decimal exponent layout.

The reader regression uses the numeric prerequisite's existing 36-case fixture
inventory, including complete canonical `sum1.data` and `parsing.data`, all
growth boundaries, exact numeric forms, strings, symbols, comments and nested
structures. Known original-reader spelling adaptations remain explicit in that
inventory; the adapted reader consumes the original strict inputs. The three
benchmark controls are generated by the existing source adapters on integration
commit `2cc5a24`, with original input bytes and repetition counts. Their normal
harness prints elapsed durations, retained as diagnostics only.

## Retained failures and corrections

All attempts remain in [diagnostics.tar.gz](diagnostics.tar.gz), indexed by
[archive.json](archive.json). [checks.json](checks.json) lists every retained
command record, source hashes, terminal status and the two outer-driver failures.
No failure was replaced by a success record.

| Attempt | Finding and correction |
| --- | --- |
| `bridge-v1` | New numeric fixture needed the newly exported arbitrary-radix integer parser; added its concrete export. |
| `bridge-v2` | Nineteen float text mismatches exposed Chez subnormal precision suffixes; stripped the suffix before interpreting exponent layout. |
| `bridge-v4` | The scalar oracle omitted the lexical `+` from a positive imaginary numerator; corrected the expected descriptor and preserved the sign. |
| `bridge-v6` | A reused Node negative-case harness expected a catchable trap; Rust correctly terminated through WASI. Each negative call now owns a fresh supervised process. |
| `bridge-v8` | Adding closed-handle probes left the fixture dispatch unclosed; the source scanner rejected it before scalar execution. Replaced the nested fixture dispatch with a linear case macro. |
| `readers-v1` | The diagnostic expected an `OK` marker absent from the unchanged upstream harness. The Sum1 child succeeded; the final checker uses the existing CSV result parser. |

The archive contains command outputs, failed and successful source snapshots,
generated exact Chez programs, input/oracle records, link records and native
build metadata. Executables stay in the isolated local build directories;
their final hashes are recorded in `checks.json`. The final scalar snapshot
precedes the addition of the three Rational-observer exports and reader-control
driver. Those changes affect only the subsequently validated reader observers
and integration checks; the scalar boundary is unchanged.

## Reproduction and focused review

With the numeric prerequisite and bridge integrated and a current scalar runtime:

```sh
python3 tests/strict-numbers/check-chez-bridge.py \
  --runtime build/wasm-runtime/wasm32-wasip1/release/snail_runtime.wasm \
  --reader-root . --output build/chez-numeric-bridge-check
```

The checker reuses the reviewed process supervisors and existing numeric,
reader and benchmark fixtures. It rejects an existing output directory and
retains terminal records before asserting results. No separate measurement or
generic testing framework is introduced. Scheme formatting, Python compilation
and whitespace checks passed for the changed source files.

The pinned simplify pass used a fresh Astra/max explainer with no files or
history, followed by informed critique. It retained lexical descriptors, one
cached classification, owned handles and private library scopes. The critique
rejected replacing Scheme arbitrary arithmetic with host bignums, using binary64
parsing to validate exact decimal syntax, and claiming formatting equivalence
from round trips alone. The grammar and effective-scale rules were reconciled
with the numeric implementation. Coherent exhaustive ABI dispatches, record
definitions and integration tests remain longer than the ten-line target;
splitting them into forwarding stages would conceal their contract.
