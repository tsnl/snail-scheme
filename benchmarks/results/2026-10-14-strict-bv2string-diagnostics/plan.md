# Bounded bv2string attribution

The authority is the finalized `bv2string-attempt4` preparation and the separate
42-process six-system clean campaign. This investigation changes diagnostic
hosts and a counter derivative, with no production source, compiler or optimizer
change. The full input remains count 100, 1,000 stress roundtrips, maximum 1,000,
expected failures 0. Every outer invocation resets the RNG, includes the sanity
roundtrip, performs all three conversions and compares the results. The full
internal trace already retained by preparation covers **one** canonical
invocation, not all 100; this investigation reuses that evidence.

1. Sample the unchanged optimized Snail V8 module once, after initialization and
   around the original worker clock, including its original host assertion.
   Keep the profiler's full raw tree, samples, intervals and bracket timestamps.
2. Observe GC events in a separate unchanged-module invocation. Classify events
   by their occurrence intervals, retain whole crossing events, record delivery
   batches and a bounded drain. The drain does not prove complete delivery.
3. Enable existing collector statistics on the unchanged selected native binary
   with its default heap policy. These are whole-process requested bytes and
   collector mark/sweep brackets, including initialization. They are neither RSS
   nor a worker-only allocation ledger.
4. Count executed sites in a separate post-optimization WAT derivative: hot loop
   entries, RNG closure calls and arithmetic/capture loads, packed/scalar element
   operations, index narrowing, readiness/ordered predicates, and constructor
   requests and requested elements. Erasing additions must recover
   the exact original optimized WAT. Extra locals are I32 only; no diagnostic
   reference storage is introduced. Array requests are counted after the length
   operand and before allocation; no separate completion counter is claimed.
   The changed guest may have different JIT
   code and physical lifetimes; its durations are not performance samples.
5. Print only RNG function89's V8 machine code from an unchanged-module full run,
   recording the actual available Node flags and every generated byte. Separate
   Liftoff and optimized code and check actual division/remainder instructions
   before attributing the residual WAT arithmetic to hardware division.

Optional Rust sampling uses the unchanged optimized Wasm and brackets synchronous
`WASI.start` after compilation/instantiation. That scope includes input, reporting
and exit beyond Rust's internal `Instant` clock, and is sampled more frequently
because the workload is short. It cannot provide a matched worker-only share.

All started guest/tool attempts are retained before validation. Each command has
one owned process group, a 120-second deadline, regular raw capture files and
group cleanup after normal exit or failure, including sleeping/stopped children
that close their capture pipes. The VM/tool commands are assumed not to create
new sessions to escape that group. Setup failures and any replay failures remain
in the archive. There are no automatic replacement samples.

The diagnostics run outside clean timing, while unrelated work may be active.
Only CPU 5 is selected; scheduling, desktop activity, sampling/observation,
tiering and the await between initialization and profiler start can alter heap
state and interval attribution. A profile leaf combines its entire function's
checks, loads, arithmetic, allocation and inlining. Site requests are executed
Wasm operations, not retired machine instructions, physical allocations or
isolated costs. Requested/completed distinctions are explicit; all counts fit
signed I64 under the fixed bounded workload. No clean campaign or production
fix is part of this investigation.

The measured V8 module is 8,208 bytes,
`c9ba1e18d65ead5db6cc005d9486e7275c14f9e8c91875edaa68e2ae59d7b1d6`.
Both native builds were supplied that module, then their mandatory native
re-entry Binaryen pass produced a distinct 9,721-byte module,
`2463c3f837b5133d6a622fe0d690da47cffb464bbda63d2f90f000b27649e41e`.
The selected native executable remains
`bc586c42b31ef7e9e36d156fc803afb45c69f411362d0cf2bea20333596d1f5c`.
Native counters and V8 samples therefore concern their actual built artifacts;
sharing a supplied module does not establish identical final lowering.

The original and adapted Chez controls remain separate. Rust stores UTF-8 bytes,
uses usize RNG state and can inline/strength-reduce constants, with deterministic
Drop; Snail uses I64 RNG arithmetic and closure/Ref representations, I32 scalar
String blocks and packed I8 bytevectors under V8 GC. Native array elements occupy
8-byte slots under the precise Immix collector. The measured controls do not
isolate representation, ownership or collector mechanisms. Rust folds the fixed
seven-byte initial sanity vector, while its stress loops retain the conversions,
allocations, comparison and frees.
