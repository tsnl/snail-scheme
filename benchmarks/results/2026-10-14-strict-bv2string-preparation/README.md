# Complete bv2string preparation

The canonical benchmark is prepared for strict Snail on V8 and the actual native
backend, original and adapted Chez, and the unchanged Rust reference on native
and V8/WASI. This report contains correctness and artifact evidence. It contains
no clean timing campaign and does not increase the historical measured coverage
of 33/57 benchmarks.

The compiler basis is `b276dfe`; production Wasm always passes through Binaryen,
including the optimized Wasm supplied to the native backend. The upstream suite
revision is `85f6acdc4cc4e2b857f307ba56bd0ba931dcccd1`. Original source SHA-256 is
`35f0046a3170258c6ed37aafce34676fada15b6cd4d340fbff92eeb22049b125`.
The unchanged input has count **100**, stress tests **1000**, maximum size
**1000**, and expected failures **0**; its SHA-256 is
`d024a11a192c89d8353c52144a35a292077f4a702f9ab262fbaaf52c015ae2a9`.

## Source correspondence

The complete original kernel and copyright remain in both controls. Exact,
counted replacements and their reversal are retained in
`prepared/bv2string/reversible-source-edits.json`, along with complete-source and
kernel patches. The original RNG recurrence, draw order, initial sanity test,
1,000 stress tests, all three conversion operations, and every string comparison
remain. Both opacity calls occur within each original invocation. The outer
loop performs all 100 invocations.

RNG mutation becomes a fresh local `Ref I64`, initialized to one on every
invocation. The global failure list becomes a `Ref (List String)` and retains
its lifetime and prepend order. The concrete test boundary takes a String name
and two Bool values. Failure messages retain the original prefix, complete name
and newline, emitted through a typed Char import. No diagnostic is discarded.

The unused even-length and multiple-of-four generators remain in the checked
kernel and have separate executable probes. The even-length generator adds one
to odd lengths, exactly as the original does. The original rational expression
`round(n/4)` becomes an exact integer quotient/remainder calculation for its
nonnegative domain, with ties to the even quotient. For example, lengths 2, 6,
10 and 14 round to 0, 8, 8 and 16 after multiplication by four. The omitted
`do` result becomes Unit. These changes are disclosed in the reversible ledger.

The adapted Chez control uses those same kernel edits, with native Chez
bytevectors/UTF-8 conversions and small compatibility definitions for refs,
annotations, Unit and diagnostics. Its only outside-kernel edit dereferences the
failure list when the original harness computes its length. Original Chez uses
the unchanged kernel and original harness. Both retain the original predicate.

## Validation boundaries

Raw and optimized Scheme Wasm, actual native, original Chez and adapted Chez
each execute count 1, 2 and the unchanged count 100. Diagnostic hosts establish
two opacity calls per invocation, including 200 at full count. A separately
compiled native provider removes only counter increments and also passes count
100. Its optimized Wasm input is byte-identical to the counting build's input.

Thirteen separate fixtures compare complete observation sequences across all
five Scheme executions, for 65 successful stream checks. The canonical trace
contains **3,476,209 little-endian u32 fields** and has SHA-256
`206b9db498985fcea1b6bdb458de81388a4c2e4f1a92418285b65562519fe35e`.
It covers **one complete invocation's 1,001 roundtrips**, rather than an internal
trace of all 100 invocations. Separate unchanged count-100 runs, a repeated-call
fixture, opacity counts and retained loop/call-chain inspection support the
outer-loop correspondence.

The independent Python oracle implements integer RNG arithmetic and Python
UTF-8 conversion. Observations include every RNG state/result, generated byte,
first decoded scalar, re-encoded byte, second decoded scalar, and complete
failure-name list. Both observation lengths and every field must match. The
first bytevector is independently anchored to `[42, 16, 6, 43, 36, 0, 21]` by the
existing Rust unit test. Other fixtures cover the larger-bound RNG threshold,
all ASCII bytes, unused generators, every rounding input from 0 through 1039,
and RNG reset across repeated calls.

Negative tests exercise both mismatching Bool directions plus both passing Bool
combinations. They preserve names containing NUL, lambda and an emoji, exact
emitted text, and reverse failure-list order. The comparison Bool itself is not
a direct observation field: every original comparison still reaches the
original test, observed strings independently establish equality, and the
negative fixtures validate the typed boundary.

The unchanged Rust reference passes its existing unit test and full-count native,
raw Wasm and optimized Wasm runs. A reversible observer derivative compares the
same complete single-invocation canonical stream on all three Rust targets.
Its native LLVM and optimized Wasm retain the conversion/copy/comparison paths;
the inspection and extracted function bodies are archived separately.
The optimized Rust compiler constant-folds the first sanity bytevector into
allocation and stores of the seven known bytes. Its 1,000 stress roundtrips keep
the RNG path. This permitted source optimization means the initial vector does
not execute an identical runtime RNG sequence in the unobserved Rust artifact.

## Representation and lifetime differences

Scheme bytevectors use an owned packed i8 array in Wasm. Scheme String stores
Unicode scalar values in I32 buffers; the same library code performs strict
validation/counting before allocation and filling. The current native executor
stores every array element in an eight-byte slot, including these byte and
character arrays. This is a measured-platform limitation, not packed native
storage.

Rust uses owned UTF-8 String buffers and `Vec<u8>`, with three owned conversion
operations per roundtrip. Empty buffers need not make physical heap allocations.
Rust frees owned buffers deterministically; the Scheme backends use their
respective collection mechanisms. Rust accumulates a numeric failure count,
while Scheme retains global failure names. The canonical zero-failure workload
is validated equivalent; arbitrary failing-input equivalence is not claimed.
The existing Rust report label says `rust-wasm` on both builds; artifact type
and the frozen command distinguish native from Wasm.
Strict inputs and RNG arithmetic use I64. Rust uses `usize`: 64 bits on this
native target and 32 bits on WASI. The canonical recurrence's largest
intermediate is 368,268,670, and its requested bounds are at most 1000, so this
input fits all three representations. The supplemental I64 larger-bound RNG
checks do not establish arbitrary-width equivalence for the Rust/WASI port.

## Attempts, review and replay

The archive preserves all four preparation attempts and the initial strict
compile smoke artifact. Attempt 1 failed because a host-only C pointer function
was mistakenly declared in the scalar provider header. Moving it to the native
entry corrected that harness boundary. Attempt 2 passed the five Scheme targets
and Rust native. Attempt 3 added the non-counting native provider and Rust/WASI:
raw Rust passed, but V8 rejected the optimized module's compact import encoding.
The overly broad Binaryen `--all-features` flag caused that rejection. Attempt 4
uses the established explicit Rust/WASI feature set and preserves both raw and
optimized outputs. Neither failure was a timeout or a Scheme compiler defect.
Probe-only Rust unused-import warnings remain in their build logs.

[The focused simplify review](simplify-review.md) records the fresh no-history
behavioral explanation, one informed critique, scope decisions and local code
inspection. The final checks and artifact identities are machine-readable in
`checks.json` and `timing-plan.json`. Source/tool/library hashes, input bytes,
generated source, commands, stdout, stderr, statuses and all attempted build
artifacts are retained in `artifacts.tar.xz` and its per-file `manifest.json`.
