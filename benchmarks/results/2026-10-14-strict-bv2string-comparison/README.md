## Retained work and representation

The optimized Scheme stress and sanity paths retain two decodes, one encode,
and the complete string comparison, while the outer path retains both foreign
opacity calls and its original count test. Corresponding native LLVM retains
these paths. Rust's optimized roundtrip retains three allocation/copy sites,
two UTF-8 validations, `memcmp` and owned-buffer frees. These are retained static
paths, not dynamic allocation counters; empty buffers need not allocate payload.

The Rust compiler folds the first sanity bytevector into allocation and stores
of the seven known bytes `[42, 16, 6, 43, 36, 0, 21]`. The stress loops retain
their RNG work. The benchmark source permits this optimization, so the
unobserved Rust artifact does not execute identical RNG operations for that
initial vector. The observer derivative preserves all RNG events for its
separate sequence comparison.

Scheme's Wasm bytevectors use packed i8 arrays; its Strings store Unicode
scalars in I32 buffers. The actual native executor currently reserves an
eight-byte slot per array element, including bytes and characters. Rust uses
owned UTF-8 Strings and byte vectors and frees them deterministically. The
Scheme backends use their own collection mechanisms. These measurements do not
isolate the cost of encoding width, padding, collection or code generation.

Scheme preserves its global failure-name list and typed diagnostic output.
Rust accumulates a numeric failure count. Their canonical zero-failure results
and buffers agree; arbitrary failing-input equivalence is not claimed. The
original integer recurrence remains within its numeric range, and the unused
multiple-of-four generator retains exact nonnegative ties-to-even rounding.
Strict uses I64; Rust uses 64-bit native `usize` and 32-bit WASI `usize`. The
canonical recurrence fits signed 32-bit arithmetic and uses bounds at most 1000.
The larger-bound supplemental Scheme probes do not establish arbitrary-width
Rust/WASI equivalence.
All supplemental generator/range/negative probes remain outside timing.

## Clock and campaign boundaries

The frozen [plan](../2026-10-14-strict-bv2string-preparation/timing-plan.md) and
[runner](../2026-10-14-strict-bv2string-preparation/measure-six.py) were reviewed
before an explicit quiet-window release. The runner hash is
`0983e6dd2e1548cf271a395af5d72238e37626079085ce1f5c3e1808989b1ab1`;
the JSON plan hash is
`580ef63bc7581b4d7e158c40e7f935aabd41003eb500b2a496204e9cb1b56ad7`.
It verified 384 frozen identities before every process and again at completion.
The plan's awaiting-release status is retained as the original preflight record;
the explicit release and completed campaign are recorded in `quiet-window.json`.

Processes ran serially on CPU 5 with default V8 tiering. One complete first
round was discarded; six retained rounds rotated order so every system occupied
each position once. Other agents acknowledged that their builds, probes,
compression, tests and measurements were stopped. No archive work or source
edits occurred during the campaign.

Process startup, program loading, instantiation and initial input setup are
outside the workload clocks. Strict V8's host result assertion is inside its
clock. Native times `bench` including its guest predicate, with host reporting
and final cleanup afterward. Chez uses the original jiffy interval, including
the final predicate and ending `current-second` read. Rust includes the original
100-call loop, result assertion (including expected-value numeric parsing), and
entry to `report` before its elapsed read. All terminal output follows the
respective workload clock. Native and WASI Rust share this unchanged source.

Every sample had a 300-second deadline and required zero status, empty stderr,
exact output framing, a valid elapsed value and the canonical accepted result.
The selected native provider reported zero diagnostic counters. The inherited
Rust CSV label says `rust-wasm` for both binaries; commands/artifacts identify
the native and Wasm rows correctly.

All requested Node/debug/preload and native-GC override variables were absent
and recorded. CPU availability and inherited environment were checked before
every sample. Hardware model and governor were captured **after** the campaign,
not before; CPU 5 then reported `powersave`. The runner did not establish a
pre-run governor observation despite that item in the written plan. No claim
of fixed CPU frequency or a captured pre-run governor is made.

Owned process groups were killed after normal completion as well as timeout.
Every bounded `/proc` check found no live group members. Zombies count as
stopped, rather than proof that all adopted process-table entries disappeared.
The separate process clock includes launch, capture, kill signaling, leader
reaping and this group check. Raw capture-plus-signal times are also retained.
